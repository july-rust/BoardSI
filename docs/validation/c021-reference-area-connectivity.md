## Source-only feature contract

- Optional `reference_area_v13::encode` Rust interface and `--reference-area-v13 RA RB NET_REF 2` importer CLI; no legacy V1–V12 behavior changed. Qt provides separate opt-in risk display and stale-source/selection invalidation.
- Reparse exact PADS V9.4 MILS source and bind original SHA-256, Source Area identifiers, Net label, Layer and identical Canonical polygon vertices. Accept **exactly two**, hole-free, source-owned, axis-aligned `COPCLS` rectangles on the same declared Reference Net and Layer. Canonical Area electrical Net remains unverified; no connectivity graph edges are created.
- Classify strictly **positive-area source-rectangle overlap**, zero-area edge/corner boundary touching, and one-tick or greater disconnected gap. These are **geometry-only candidate/risk** states, never a demonstrated electrical bond, plated continuity or fabricated fill.
- Separate Rust API route candidate validates an optional straight, axis-aligned trace centreline supported strictly by the union of both source rectangles on the adjacent Reference Layer; rejects merely intersecting L-shaped fills, boundary rides, diagonal routes and unsupported inventory. The CLI and Qt area-only mode do **not** claim this optional route result.
- Fail closed for different Net/Layer, uncertain source ownership, cutouts, non-rectangular shape, more than two Areas, canonical mismatch, stale file, ambiguous geometry, or invalid trace. Risk UI and cache never promote results to physical Solver readiness.
- Tests: `crates/boardsi-import/tests/c021_reference_area_v13.rs` (6 source-geometry/negative Rust synthetic tests), plus actual Rust→Qt `--c021-area-selftest` on Native Windows x64/ARM64 and macOS ARM64 and Qt Linux offscreen CTest.
